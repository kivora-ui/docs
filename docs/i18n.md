# Español e inglés sin cambiar las URL

La elección explícita ES/EN tiene prioridad y se guarda un año en la cookie `kivora-locale` (Path=/, SameSite=Lax, Secure bajo HTTPS). El selector refresca los componentes del servidor sin navegar a otra dirección. Sin cookie válida, se toma el idioma preferido de `Accept-Language`, ordenado por su peso: español regional se resuelve a `es`; cualquier otro idioma o ausencia de idioma se resuelve a `en`.

El layout raíz proporciona el idioma al cliente y al atributo `html[lang]`. No se modifica el DOM para traducir texto ni se espera a la hidratación para detectar el idioma. Los metadatos, datos estructurados y recursos Markdown usan la misma función de detección. Los slugs, imports y nombres de las propiedades de la API no se traducen.

## Mantener las traducciones

- Los textos originales en español permanecen en los componentes, `catalog.ts` y `content.ts`.
- `app/_lib/i18n/en.json` relaciona los textos originales con su traducción inglesa. `t(texto, valores)` permite interpolar nombres y cantidades sin traducir datos del usuario.
- `app/docs/localized.ts` localiza el catálogo y las guías sin mutar los datos originales.
- Al cambiar ejemplos o sus traducciones, ejecutar `npm run docs:translate`. Genera `app/docs/examples.en.json` traduciendo textos JSX, literales y el locale de los ejemplos. Mantiene imports, identificadores y APIs.
- Ejecutar `npm run test`, `npm run docs:check` y `npm run test:e2e`. Los ejemplos de ambos idiomas deben compilar y funcionar. Las pruebas de cobertura detectan descripciones, guías y atributos sin traducción.

El equipo de demostración sigue en sessionStorage. Los nombres, roles y otros datos introducidos por visitantes se conservan tal como fueron escritos.
